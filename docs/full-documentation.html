Dokumentasi Produk · v4.4.0

Semua fitur QA Flow Master Pro, dan cara memakainya.

Ekstensi Chrome/Edge untuk merekam interaksi web, menyusunnya menjadi test case, menjalankannya berulang dengan data berbeda, dan membiarkan AI yang mengeksplorasi halaman untuk Anda — lalu memvalidasi semuanya lewat CLI Playwright dan CI.

01 · Ringkasan

Apa itu QA Flow Master Pro

QA Flow Master Pro adalah recorder Chrome sekaligus runner Playwright produksi. Test yang direkam di ekstensi diekspor sebagai JSON, divalidasi terhadap skema, dijalankan terhadap dataset, dan bisa dipakai sebagai gerbang kualitas (quality gate) di CI. Semua ini berjalan local-first — tidak wajib akun, kunci API provider AI tersimpan di perangkat, dan tidak ada proxy backend antara ekstensi dan model AI.

Recorder & Authoring

Rekam interaksi nyata, selector CSS dibuat otomatis dengan hingga 8 fallback, atau tulis langkah manual dari 32 aksi yang tersedia.

QA Copilot

Buat skenario test dari bahasa natural atau screenshot, dengan mode diskusi (Plan Mode) sebelum eksekusi.

AI Sharing Agent

AI menjelajahi halaman secara otonom — klik, isi form, verifikasi hasil — lalu menyerahkan test case jadi untuk disimpan atau dijalankan.

Input Data Massal

Jalankan satu form berulang untuk ratusan-ribuan baris dataset, dengan progres langsung, lanjut-walau-gagal, dan retry baris gagal.

Bug Exporter

Ekspor bug satu klik ke Slack, Teams, GitHub, Linear, atau Jira lengkap dengan konteks langkah reproduksi.

Quality Gate CI

Validasi skema, pemindaian secret, HTTP tidak aman, dan kerentanan dependency — otomatis lewat GitHub Actions.

Catatan

Dokumen ini menjelaskan apa yang bisa dilakukan tiap fitur dan bagaimana memakainya. Untuk pola penulisan suite JSON tingkat lanjut dan konfigurasi CI, lihat docs/expert-guide.md. Untuk detail desain UI, lihat docs/ui-ux-guide.md.

02 · Mulai

Instalasi & quick start

Memasang ekstensi (mode developer)

  1. Buka halaman ekstensi. Kunjungi chrome://extensions (atau edge://extensions) dan aktifkan Developer mode di pojok kanan atas.
  2. Muat folder proyek. Klik Load unpacked, lalu pilih root folder repositori ini (folder yang berisi manifest.json).
  3. Buka Side Panel. Klik ikon ekstensi di toolbar browser — QA Flow Master Pro tampil sebagai panel di sisi kanan, bukan popup, sehingga tetap terbuka saat Anda berpindah tab.
  4. Rekam atau tulis langkah, lalu ekspor JSON. Suite yang diekspor bisa divalidasi dan dijalankan ulang dari command line.

Menyiapkan CLI runner

Runner CLI menjalankan suite JSON yang sama dengan Playwright — dipakai untuk regresi lokal maupun CI.

# pasang dependency & browser Playwright
npm ci
npx playwright install chromium

# pemeriksaan cepat sebelum menjalankan apa pun
npm run check          # syntax-check semua modul
npm test                # unit test

# validasi & jalankan satu suite
npm run qa:validate -- suites/smoke.json
npm run qa:run -- suites/smoke.json

Hasil eksekusi ditulis ke folder artifacts/: laporan HTML (html-report/index.html), junit.xml, results.json, serta screenshot/video/trace kegagalan.

04 · Menulis Test

Merekam & menulis langkah manual

Merekam interaksi nyata

Klik Rekam di tab Builder lalu lakukan aksi seperti biasa di halaman: klik, ketik, pilih dropdown, centang checkbox. Setiap interaksi otomatis menjadi satu langkah tes dengan selector CSS yang tangguh — sistem mencoba hingga 8 selector fallback (id, data-testid, teks, posisi DOM, dst.) supaya test tidak rapuh saat markup berubah sedikit.

Tombol Layar merekam video sesi browsing sebagai bukti eksekusi, tersimpan di riwayat video (tab Reports).

Menambah langkah manual

Gunakan form di bawah daftar langkah untuk menambah langkah tanpa merekam — cocok untuk assertion, wait, atau aksi API/network yang tidak berasal dari klik nyata:

  • Tipe Aksi — pilih dari 32 aksi terdaftar (lihat referensi kosakata aksi).
  • Target CSS Selector — wajib untuk aksi yang menyasar elemen (mis. click, fill); dikosongkan otomatis untuk aksi tanpa target seperti press, go_back, go_forward, atau wait.
  • Value / Expected Text — nilai yang diisi atau nilai yang diharapkan, tergantung aksinya.
  • Group, Timeout, Requirement ID, Risk — metadata opsional untuk traceability dan governance QA Readiness.
Catatan

Delay antar langkah, jumlah retry otomatis, opsi stop on error, dan opsi rekam video saat run diatur di toolbar tab Builder, tepat di sebelah tombol Jalan.

06 · Menulis Test

Dataset & data dummy

Tab Presets menyediakan dua cara mengisi test dengan data: variabel dummy siap pakai, dan dataset yang diimpor sendiri.

Variabel data dummy

Klik chip mana pun untuk menyalin placeholder-nya, lalu tempel ke kolom Value sebuah langkah fill. Placeholder digantikan dengan nilai realistis secara otomatis saat langkah dijalankan.

{{email}}{{fullname}}{{phone}} {{nik}}{{password}}{{address}} {{city}}{{postcode}}{{company}} {{job_title}}{{npwp}}{{cc_visa}} {{cc_master}}{{cc_amex}}{{price_idr}} {{date_past}}{{date_future}}{{url}} {{ip_v4}}{{mac_address}}{{uuid}} {{lorem_ipsum}}{{user_agent}}{{timestamp}} {{randomtext}}

Data Indonesia (NIK, NPWP, No. HP, alamat) dibuat mengikuti format yang valid secara struktur, untuk kebutuhan testing lokal.

Mengimpor dataset (CSV/JSON)

Klik ikon import di kartu Presets untuk mengunggah file CSV atau JSON berisi banyak baris data — setiap baris menjadi satu set nilai yang bisa dipakai lewat placeholder {{nama_kolom}} sesuai header kolomnya. Dataset mendukung hingga 20.000 baris.

Peringatan

File Excel (.xlsx/.xls) bisa dipilih di dialog file, tapi belum diparse langsung — parser Excel di ekosistem npm punya kerentanan keamanan yang belum ditambal, sehingga sengaja tidak disertakan. Simpan/ekspor dulu sebagai CSV dari Excel atau Google Sheets ("Save As" / "File → Download → CSV"), lalu impor file CSV tersebut di sini.

Gunakan pemilih Environment dan Dataset aktif di atas kartu untuk berpindah antar konfigurasi tanpa mengedit langkah tes.

07 · Menulis Test

Input data massal (bulk data-entry)

Untuk kasus nyata seperti "isi form ini untuk 500 baris data pelanggan dari spreadsheet": rekam satu alur (isi form → submit → verifikasi → buka form lagi) sebagai test case biasa, lalu jalankan otomatis untuk setiap baris dataset — mirip Google Forms yang menerima banyak submission berurutan.

Cara pakai

  1. Rekam satu siklus isi-form. Gunakan placeholder {{nama_kolom}} pada langkah fill agar setiap baris dataset mengisi nilai yang berbeda. Sertakan langkah untuk membuka ulang form di akhir siklus.
  2. Impor dataset CSV/JSON. Header kolom harus cocok dengan nama placeholder yang dipakai di langkah fill.
  3. Klik "Jalankan Semua Baris Dataset". Tombol ini muncul di tab Presets begitu ada dataset aktif dengan baris data. (Alt+klik tombol Jalan di tab Builder adalah shortcut yang sama.)
  4. Pantau progres langsung. Banner eksekusi menampilkan baris ke berapa yang sedang diproses dari total baris, tanpa harus menunggu semuanya selesai untuk tahu statusnya.

Lanjut walau gagal

Satu baris gagal tidak menghentikan seluruh batch — semua baris tetap diproses, lalu ringkasan akhir memisahkan mana yang sukses dan mana yang gagal beserta nomor barisnya.

Retry baris gagal

Ringkasan akhir menawarkan tombol untuk menjalankan ulang hanya baris yang gagal, tanpa mengulang baris yang sudah sukses.

Resume otomatis

Jika batch terhenti (browser tertutup, koneksi putus, dsb.), checkpoint tersimpan otomatis. Saat dataset yang sama dijalankan lagi, sistem menawarkan melanjutkan dari baris terakhir yang belum selesai.

Tip

Minta QA Copilot membuatkan alur ini langsung: sebutkan nama form dan kolom-kolomnya, Copilot akan menyusun langkah dengan placeholder yang benar dan menyertakan langkah buka-ulang form di akhir — lihat bagian "Bulk data-entry" pada prompt sistemnya.

Tombol Stop di tab Builder menghentikan batch yang sedang berjalan kapan saja; baris yang sudah selesai tetap tercatat di checkpoint.

08 · AI Copilot

QA Copilot: chat & generate test

Tab Copilot adalah percakapan dengan AI (Gemini, Claude, atau DeepSeek — dikonfigurasi di AI Settings) yang memahami maksud Anda: membuat test case baru, menjawab pertanyaan seputar QA, atau mengerjakan tugas ahli seperti menyusun mock API atau laporan bug.

Yang bisa diminta

  • Generate test case — "Buatkan test login gagal dengan password salah" menghasilkan langkah-langkah siap pakai lengkap dengan assertion, ditampilkan sebagai kartu langkah yang bisa langsung disimpan.
  • Test negatif & boundary value — diminta secara eksplisit, Copilot menyusun skenario tepi (input kosong, karakter maksimal, format tidak valid) sebagai bagian dari kualitas test, bukan hanya jalur bahagia.
  • Lampiran gambar/screenshot — kirim tangkapan layar sebuah halaman atau bug, Copilot membaca konteks visualnya.
  • Tugas ahli (expert task) — mock API/page.route, menyusun laporan bug terstruktur, dan pertanyaan self-healing selector ditangani dengan prompt khusus yang lebih teknis.

Verifikasi selector otomatis

Sebelum langkah hasil generate ditampilkan, Copilot memeriksa tiap selector terhadap halaman yang sedang aktif. Selector yang tidak ditemukan diberi badge peringatan ⚠️ pada kartu langkahnya, beserta ringkasan jumlah selector yang belum terverifikasi — sehingga Anda tahu langkah mana yang perlu dicek ulang sebelum menjalankan test, bukan menemukannya saat run gagal.

Catatan

Selector dengan sintaks khusus Playwright (mis. :has-text()) tidak bisa diperiksa lewat querySelectorAll native browser, sehingga dibiarkan tanpa badge — ini bukan berarti selector tersebut valid, hanya belum bisa diverifikasi otomatis.

Format jawaban

Jawaban percakapan (bukan kartu langkah) memakai format markdown lengkap: bold untuk istilah penting, kode inline untuk selector/nilai, daftar bernomor untuk urutan, dan kotak highlight bergaya Note/Tip/Warning/Important untuk poin yang perlu menonjol — bukan lagi paragraf teks polos.

09 · AI Copilot

Plan Mode: diskusi dulu, eksekusi kemudian

Toggle Plan di tab Copilot mengubah alur permintaan test-generation menjadi dua tahap: AI menjelaskan rencana pengujian dalam bahasa biasa terlebih dahulu, dan baru menyusun langkah nyata setelah Anda menyetujuinya secara eksplisit.

Alurnya

  1. Aktifkan Plan Mode. Nyalakan toggle Plan di header tab Copilot.
  2. Minta sebuah test. Contoh: "Buatkan test case checkout dengan kupon diskon."
  3. Baca rencananya. AI menjawab dalam bentuk diskusi murni — skenario apa yang akan dicakup, asumsi apa yang dipakai — tanpa langsung membuat langkah tes.
  4. Konfirmasi untuk eksekusi. Balas dengan konfirmasi singkat seperti "Ya, lanjutkan", "oke", atau "jalankan" — barulah langkah tes nyata dibuat dan ditampilkan sebagai kartu langkah.
Penting

Jika Anda ingin mengubah arah rencana sebelum eksekusi, balas dengan revisi (bukan kata konfirmasi) — mis. "tambahkan juga skenario kupon kedaluwarsa" — Copilot akan menyesuaikan rencana dan menunggu konfirmasi lagi, bukan langsung mengeksekusi rencana lama.

Plan Mode berlaku khusus untuk permintaan pembuatan test; pertanyaan pengetahuan QA umum tetap dijawab langsung tanpa tahap rencana.

10 · AI Copilot

AI Sharing Agent: eksplorasi otonom

Toggle Agent di tab Copilot memberi AI kendali langsung atas halaman aktif. Alih-alih hanya menulis langkah dari deskripsi Anda, agent benar-benar membaca DOM halaman, mengklik, mengisi form, dan memverifikasi hasilnya — lalu menyerahkan test case jadi di akhir sesi.

Cara berpikir agent

Setiap iterasi mengikuti kerangka kerja QA engineer manusia: amati keadaan halaman → ambil aksi → verifikasi apakah hasilnya benar-benar berubah seperti yang diharapkan → jika gagal, diagnosis akar masalah (bukan mengulang aksi yang sama) → sebelum menyatakan selesai, cek ulang apakah tujuan pengujian benar-benar tercapai.

Piercing iframe & shadow DOM

Agent membaca elemen di dalam iframe same-origin dan shadow root terbuka — termasuk popup login/register yang dirender lewat kerangka framework modern, bukan hanya dokumen teratas.

Deteksi konteks halaman

Mengenali popup/modal, elemen disabled, indikator loading/skeleton, dan proteksi CAPTCHA/bot sebelum memutuskan aksi berikutnya.

Navigasi browser asli

"Kembali" dan "maju" memakai riwayat navigasi browser asli (chrome.tabs.goBack/goForward), bukan simulasi JavaScript — sehingga berperilaku identik dengan pengguna sungguhan menekan tombol back/forward.

Anti-repeat & self-check

Jika agent mengulang aksi identik, ia mendapat teguran korektif sebelum berhenti paksa. Sebelum menyatakan "selesai" tanpa satu pun langkah verifikasi, agent dipaksa melakukan satu iterasi pengecekan tambahan.

Hasil akhir sebuah sesi

Setelah agent menyatakan selesai (maksimal 35 iterasi), Anda menerima:

  • Test case lengkap — siap disimpan sebagai suite atau dijalankan langsung.
  • Jika agent menemukan bug selama eksplorasi: laporan bug terstruktur (lihat Bug Exporter) dengan expected/actual/severity terisi, bukan teks generik.
Peringatan

Sebagai gerbang keamanan, agent selalu meminta konfirmasi Anda sebelum mengklik elemen yang berpotensi merusak data — tombol hapus/delete/remove, atau logout/keluar — sehingga halaman yang disusupi prompt-injection tidak bisa memaksa agent menghapus data atau keluar dari sesi diam-diam.

11 · Kualitas & Pelaporan

Visual, API & quality gate testing

Visual regression

Langkah assert_screenshot membandingkan tangkapan layar saat ini dengan baseline tersimpan, dengan ambang batas perbedaan piksel yang bisa diatur (QA_VISUAL_THRESHOLD, default 0.01).

Batasan yang perlu diketahui

Playwright menamai file baseline per sistem operasi (mis. akhiran -win32.png). Baseline yang dibuat di Windows tidak bisa dipakai apa adanya di runner CI berbasis Linux. Suite visual regression contoh karena itu dikecualikan dari loop "jalankan semua suite" di CI — tetap divalidasi skema dan gerbang keamanannya, tapi dijalankan manual/lokal saja.

API testing

Langkah api_request memanggil endpoint secara langsung (tanpa lewat UI) dan memeriksa status code serta nilai pada path JSON tertentu di body response — cocok untuk memvalidasi kontrak API secara terpisah dari UI.

Network mocking

Langkah mock_route mengganti response untuk pola URL tertentu (status, body, delay buatan) sehingga skenario seperti "server API lambat" atau "endpoint mengembalikan 500" bisa diuji tanpa bergantung pada backend sungguhan. clear_mocks mengembalikan semua rute ke perilaku aslinya.

Gerbang kualitas

AksiContoh valueKeterangan

assert_security_headers{"required": ["content-security-policy"]}Gagal jika header keamanan wajib tidak dikirim server.
assert_a11y{"disabledRules": ["region"]}Gerbang aksesibilitas axe-core; rule tertentu bisa dinonaktifkan jika memang tidak relevan untuk halaman tersebut.
12 · Kualitas & Pelaporan

Live log monitor

Tab Monitor menampilkan log console dan aktivitas network dari tab yang sedang aktif secara real-time, tanpa harus membuka DevTools.

  • Filter log — Semua / Console / Network.
  • Filter network — berdasarkan method (Semua, Gagal, POST, PUT/PATCH, DELETE), status, tipe, dan domain.
  • Tangkap body — opsi merekam isi request/response, berguna saat menyusun assertion assert_network_status atau memverifikasi payload API.
13 · Kualitas & Pelaporan

QA Readiness & governance

Kartu QA Readiness (tab Reports) mengumpulkan seluruh siklus hidup kualitas dalam satu tempat, dengan jejak audit yang tersimpan bersama export suite JSON — tidak butuh sistem eksternal untuk proyek kecil-menengah.

Requirements

Definisikan requirement dan hubungkan ke langkah tes untuk traceability requirement-ke-test.

Tambah defect / Defect board

Catat defect dan pantau siklus hidupnya di papan kanban ringkas.

Exploratory session

Catat sesi eksplorasi manual (charter, catatan, temuan) di luar test case terstruktur.

Cetak Sign-off

Hasilkan dokumen release sign-off berdasarkan status requirement, defect, dan hasil eksekusi terbaru.

Riwayat versi

Lihat riwayat revisi suite dari waktu ke waktu.

Backup workspace

Ekspor seluruh state kerja sebagai cadangan yang bisa dipulihkan.

Semua catatan governance memakai jejak audit berantai-hash (hash-chained) sehingga riwayat tidak bisa diubah diam-diam tanpa terdeteksi.

14 · Kualitas & Pelaporan

Bug Exporter

Ekspor laporan bug satu klik ke lima tujuan, lengkap dengan konteks langkah reproduksi, tanpa menyalin-tempel manual ke masing-masing tool.

SlackTeamsGitHub LinearJira

Mengatur tujuan export

  • Slack / Teams — masukkan URL Incoming Webhook masing-masing workspace.
  • GitHub / Linear — hubungkan lewat token/endpoint yang relevan untuk membuat issue langsung.
  • Jira — integrasi paling lengkap: isi Site URL, Email akun, dan API Token, lalu Test Connection untuk memverifikasi sebelum memilih Project, Issue Type, Priority, dan Labels.

Judul laporan bisa diisi manual, atau — jika laporan berasal dari sesi AI Sharing Agent — sudah terisi otomatis dengan expected/actual behaviour dan tingkat keparahan berdasarkan apa yang ditemukan agent selama eksplorasi.

Tip

15 · Kualitas & Pelaporan

Laporan & riwayat eksekusi

Tab Reports menyimpan hingga 20 riwayat eksekusi terakhir beserta metrik total/passed/failed/status per run, riwayat video recording, serta kartu Export & Report Suite untuk mengekspor suite JSON siap dipakai CLI runner atau CI.

Untuk laporan yang dihasilkan CLI runner (bukan dari dalam ekstensi), lihat folder artifacts/ setelah menjalankan npm run qa:run — berisi laporan HTML interaktif, JUnit XML untuk integrasi CI, JSON mentah, serta dashboard tren dan skor flaky test jika dikonfigurasi.

16 · Otomasi & CI

CLI runner & CI/CD

Perintah CLI

# cek sintaks semua modul
npm run check

# unit test
npm test

# e2e: boot ekstensi asli di Chromium
node --test tests/extension/extension.test.mjs

# validasi suite terhadap skema JSON
npm run qa:validate -- suites/nama-suite.json

# gerbang keamanan: secret, HTTP tidak aman, dependency
npm run qa:security

# jalankan suite
npm run qa:run -- suites/nama-suite.json

# siapkan storage-state login yang bisa dipakai ulang
npm run qa:auth

.github/workflows/ci.yml menjalankan dua job berurutan setiap push/PR:

  • quality — checkout, setup Node 20, npm ci, npm run check, npm test, validasi skema semua suite, dan gerbang keamanan untuk tiap suite.
  • e2e (butuh quality lulus) — pasang Chromium Playwright, jalankan test e2e ekstensi, lalu jalankan setiap suite di suites/ kecuali visual-regression.json (dikecualikan karena keterbatasan baseline per-OS di atas). Artefak diunggah meski job gagal.

Catatan keamanan

  • Kunci API lokal-only — kunci provider AI tersimpan di storage khusus qa_ai_settings dan tidak pernah ikut dalam payload sinkronisasi cloud.
  • Redaksi cloud — kredensial dalam thread Copilot, session secret, dan pengaturan video di-redact sebelum dikirim ke cloud (jika sinkronisasi Supabase diaktifkan).
  • Pertahanan prompt-injection — DOM yang di-scrape dibungkus sebagai konteks tidak tepercaya; model diinstruksikan mengabaikan teks halaman sebagai instruksi.
  • Network aman — secureFetch memblokir target jaringan privat kecuali diizinkan eksplisit; target redirect divalidasi.
  • Ingestion langkah yang dikeraskan — langkah hasil AI divalidasi terhadap kontrak aksi bersama, di side panel maupun di background worker.
  • Gerbang keamanan agent — AI Sharing Agent meminta konfirmasi sebelum mengklik elemen destruktif (delete/remove/logout/keluar/...).
  • Tanpa eval/new Function — seluruh konten user/AI melewati escapeHTML/escaping markdown sebelum masuk innerHTML.
